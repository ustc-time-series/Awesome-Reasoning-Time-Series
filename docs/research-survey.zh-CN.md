# Reasoning-aware 时间序列预测：推理如何进入数值预测

检索与证据截止日期：2026-11-03。本文综合公开论文、正式会议页面和作者材料，解释研究路线及评估边界；没有复现训练或预测结果。各论文的完整元数据、版本与资源状态见仓库目录。以下分类是本综述提出的工作框架，并非领域已有的统一标准。

## 研究对象与工作定义

本文将 reasoning-aware forecasting 理解为：系统在输出未来数值之前，引入可辨认的中间计算、语义判断或行动决策，并让它参与预测生成、模型组合或预测修订。应能说明“历史与上下文 → 中间推理 → 数值输出”的接口，并通过消融或干预检验这条路径的作用。中间过程可以是文字、结构化字段、工具调用或潜在状态，不必全部表现为自然语言。

使用 LLM、加入文本协变量、输出一段解释，本身不足以证明预测包含有效推理。解释可能在数值预测之后生成，也可能只复述趋势；更低的误差也可能来自额外信息、更多采样或更强的预测器。需要分别回答：推理是否参与计算、是否改善预测、是否忠实解释了模型的计算依据。

范围也应与一般时序问答区分。例如，[TS-Reasoner：表示对齐](https://arxiv.org/abs/2510.03519)主要研究理解与推理任务；另一个同名的 [TS-Reasoner：领域工具智能体](https://arxiv.org/abs/2410.04047)研究多步分析流程。它们提供相关能力与接口，不能仅凭问答成绩推出未来数值预测更准确。

## 三类推理接口

### 1. 直接生成预测，或在潜在空间增加计算

[TimeReasoner](https://arxiv.org/abs/2505.24511)通过提示考察慢思考模型能否从时间模式和上下文推导预测；[Time-R1](https://arxiv.org/abs/2506.10630)进一步以监督微调和强化学习训练多步预测能力。两者的区别在于如何获得推理策略，而不只是输出是否更长。此类方法的核心检验是：控制输入、骨干和计算预算后，中间推理是否仍带来收益。

[ReasonCast：联合解释与预测](https://arxiv.org/abs/2608.01875)把理由和数值放入同一次自回归生成，缩短了两个输出之间的接口，但共同生成仍不自动保证解释忠实。[COUNTS](https://arxiv.org/abs/2510.01116)结合离散时序表示与可验证奖励；[TimeOmni-1](https://arxiv.org/abs/2509.24803)覆盖感知、事件感知预测和决策等任务。阅读后两者时，需要单独检查预测子任务，避免把综合推理能力等同于连续数值精度。

[Latent Chain-of-Thought](https://arxiv.org/abs/2605.11262)采用另一条路径：将隐藏状态压缩为反馈 token，再进行多轮计算。这里增加的是潜在计算步骤，而非可读理由。因此，同深度、等有效深度和共享权重循环基线尤其关键；文字解释质量并不适用于判断这条路线是否有效。

### 2. 推理控制数值模型或集成器

这类方法把语义判断与精确数值生成分工。[STRIDE](https://arxiv.org/abs/2605.08625)将推理隐藏状态投影为时序模型的连续先验；[KairosAgent](https://aclanthology.org/2026.emnlp-main.1343/)让工具增强的 reasoner 生成未来形态描述，再将其融合进 TSFM。应检查语义信号是否改变了预测器的有效计算，而不只是增加一个表示模块。

[REATS](https://arxiv.org/abs/2608.10149)输出样本级集成权重：推理决定信任哪些候选预测器。[TimeOmni-VL](https://arxiv.org/abs/2602.17149)则通过时序与图像映射，以理解结果控制生成。两者分别面临权重决策是否有效、语义控制及数值映射是否可靠的问题。

[ReasonCast：选择性语义需求预测](https://arxiv.org/abs/2608.15291)与前述联合生成论文是两项独立工作。它先判断是否需要文本推理，再将事件转换为相关性、方向、时间形状、幅度等字段，通过加性和乘性路径调整预测。此处的关键是可检验的干预接口：何时保持无文本预测、何时修订，以及修订作用于哪些时间位置。

### 3. 组织工具、记忆与反思的预测流程

[From News to Forecast](https://proceedings.neurips.cc/paper_files/paper/2024/hash/6aef8bffb372096ee73d98da30119f89-Abstract-Conference.html)用预测误差反馈修订新闻筛选逻辑，主要发生在训练与验证的数据构造循环。[AlphaCast](https://arxiv.org/abs/2511.08947)组织证据调查、预测生成和反思；[CastFSR](https://arxiv.org/abs/2608.03031)先建立数值先验，再依据上下文局部修订并检查约束。它们把推理对象从“一次输出”扩展为“何时搜集何种证据、怎样使用证据”。

[Cast-R1](https://arxiv.org/abs/2602.13802)通过轨迹蒸馏和多轮强化学习训练工具使用策略，其结构化记忆保存当前交互的诊断和中间预测。[MemCast](https://proceedings.mlr.press/v306/tao26a.html)的重点则是跨实例经验：历史模式、推理经验和一般规律共同支持检索、轨迹选择和反思。两种“记忆”承担不同职责，不能只按是否含 memory 命名归类。

[Nexus 当前版本](https://arxiv.org/abs/2605.14389)将数值锚点与宏观、微观上下文预测通过历史误差协方差进行贝叶斯合成。[SEER](https://arxiv.org/abs/2610.04109)把已观测误差分别转化为检索记忆和因果知识更新；[TimEvolve](https://arxiv.org/abs/2609.24862)则更新专家信任、候选路径选择和干预强度。后两者改变的是后续预测的组织方式，不能与同一预测窗口内的自我检查混为一谈。

这些分类可以重叠：一个智能体既可调用数值模型，也可输出文字推理。更有用的比较维度是推理产物、接入位置、可用反馈和额外计算，而非模块数量。

## 基准究竟测量了什么

[Context is Key（CiK，ICML 2025）](https://proceedings.mlr.press/v267/williams25a.html)构造必须理解文本上下文才能完成的预测任务，适合检验上下文使用。其精心设计的文本条件与开放网络检索的真实性、时间可用性是不同问题。[TSRBench（ICML 2026）](https://proceedings.mlr.press/v306/yu26m.html)同时覆盖感知、推理、预测和决策，并报告这些能力可能分离；因此需要保留任务分项，不能用综合问答分数替代预测误差。

[TFRBench](https://arxiv.org/html/2604.05364v1)提供参考推理轨迹，但构造阶段使用未来事件的 oracle 信息，并以验证分数 ≥4、MASE <1 进行结果条件化筛选；待评模型的主评估从历史输入出发。这不等于直接把未来目标交给待评模型，却使参考理由带有事后信息和成功样本选择。与参考理由的对齐程度可以反映一种质量标准，不能单独证明模型实现了纯粹的事前推理，或忠实揭示其内部依据。

[LEAF](https://arxiv.org/html/2605.16358v2)把时间可用性纳入检索核验。专家审计的 500 条样本中，未核验事件有 43 条发生未来信息泄漏，双智能体核验后仍有 8 条；应保留残余风险。其数值预测、方向分类和事件概率属于不同任务，后两者的提升不能直接外推为精确价格预测能力。

[COMMON-TSQA](https://arxiv.org/html/2610.05686v1)通过删除、打乱、置平等操作诊断数值证据使用。主分析通常保留原问题与原标签，故干预后对原标签的准确率不等于反事实正确率；论文另对可精确重算的跨序列子集更新标签。其意义在于区分输入敏感性、事实依据、推断有效性和答案一致性，而非把一种干预分数当作完整忠实性证明。

## 应怎样建立可信证据

首先区分三个时间点：标注构造、模型训练和预测发出。训练数据可以用训练目标生成理由或奖励，但训练与测试来源必须隔离；预测时可使用已公布的假期、促销计划或天气预报，不能混入事后实测天气或结果摘要。“涉及未来时段”与“在预测时不可得”并不等价。

在线反馈还需单独定义。MemCast 在真实结果可得后更新置信度；SEER 在学习阶段用可观测结果反思；TimEvolve 明确要求原点为 s、跨度为 H 的预测在 s+H≤t 后才能影响原点 t 的决策。应记录每次更新的可用时间，尤其防止重叠预测窗口提前揭示目标；并与相同信息条件下的静态系统比较。[MemCast](https://arxiv.org/html/2602.03164v2)、[SEER](https://arxiv.org/html/2610.04109v1)、[TimEvolve](https://arxiv.org/html/2609.24862v1)给出了不同形式的反馈机制。

实验至少需要分开报告：数值误差及概率校准、理由中事实是否可核验、理由是否反映实际影响预测的因素。事实正确不保证推断有效，推断通顺不保证预测准确；删除理由后输出不变，也可能是重复信息或接口未生效，需要进一步干预定位。

公平比较应匹配预测跨度、切分、可用协变量、候选模型池和计算预算，再分别消融额外上下文、推理与搜索。还应公布全部样本的失败输出、重试和回退比例，以及调用数、token、延迟和训练／检索成本。只计算有效输出的误差，或只比较最终 API 调用费，容易掩盖系统实际代价。公开仓库与可运行复现包也需区分：本次检查中，[KairosAgent 项目页](https://mldi.group/KairosAgent/)未提供代码入口，[SEER 仓库](https://github.com/BennyTMT/SEER)主要提供论文与展示材料。

## 三个值得研究的问题

以下是本文的综合判断，不是已被上述论文验证的结论。

1. 建立可执行、可干预的语义接口。将事件方向、持续时间、作用范围与预测修订明确对应，再替换、删除或扰动单个字段，检查输出是否按预期变化。需要区分“对模型计算有因果影响”与“揭示真实世界因果关系”；后者要求更强证据。
2. 建立带时间版本的证据与反馈账本。保存信息公布时间、检索版本、已提交预测和结果揭示时间，使离线回放与在线运行具有一致信息边界，并比较上下文收益、延迟反馈收益和组织策略收益。
3. 研究有预算约束的选择性推理。让系统根据证据强度和不确定性决定是否调用推理、检索或反思，并同时评价误差、校准与成本。在证据薄弱时保留数值先验，应成为可评估的行为，而非只奖励更长解释。

## 建议阅读顺序

这是一条理解接口与证据边界的路线，不是性能排名：

1. [TimeReasoner](https://arxiv.org/abs/2505.24511)：建立“把预测写成推理任务”能做什么、尚不能说明什么的起点。
2. [CiK](https://proceedings.mlr.press/v267/williams25a.html)：理解为何某些预测必须使用文本，以及如何设计上下文对照。
3. [KairosAgent](https://aclanthology.org/2026.emnlp-main.1343/)：观察语义推理怎样通过具体接口控制数值预测器。
4. [MemCast](https://proceedings.mlr.press/v306/tao26a.html)：理解跨实例经验、轨迹选择与延迟结果反馈的区别。
5. [COMMON-TSQA](https://arxiv.org/abs/2610.05686)：回到证据使用、事实正确性和解释忠实性，审视前面各路线的验证是否充分。
